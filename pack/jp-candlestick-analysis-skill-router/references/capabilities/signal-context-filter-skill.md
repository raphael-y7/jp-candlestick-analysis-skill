## I — 方法自述

这张卡是一张"信号取舍决策树"，回答的不是"这是什么形态"，而是"这个形态出现在这里值不值得行动"。核心是先校准语义：反转形态只宣告原趋势终止（汽车刹车灯亮了），之后行情可能掉头、可能横盘、也可能原样继续——所以形态本身永远不是方向指令。

流程四步：
1. 先确认存在可被"反转"的先前趋势——横盘箱体中部的任何形态都没有反转对象，直接判停不动作。
2. 再评估位置四要素：信号方向与趋势是否一致、是否落在支撑/阻挡区、是否处于超买超卖、附近有无整数关口与信号群密度。
3. 然后方向分派：信号与主要趋势同向才可开新仓；逆向信号只用于了结或保护既有头寸。
4. 行动前做风险报偿比核算，不划算就放弃。

两条常被忽略的细则：位置本身可以加持信号——略欠标准的形态落在关键支撑上仍按标准信号对待；信号出现后市场未必立即兑现，可能转为"加强"某个支撑区域——未兑现不等于失效。

## A1 — 应用示例

### 示例 1: 同一张沃尔玛日线——空头吞噬是"诱人的陷阱"，更弱的乌云盖顶反成战机
- **类型与来源**: reported_case，下书新解第 4 章图 4-5（TOP15#2）
- **问题/输入**: 1 月多头吞噬推动回升，随后出现上升缺口；两日后一根吞噬形态长阴线（空头吞噬）；几周后同一图上出现乌云盖顶。两个形态哪个值得做空？
- **方法论的使用**: 不按"形态强弱排位表"（教科书上空头吞噬强于乌云盖顶）机械选择，逐个过位置与报偿比：空头吞噬前方不远处就是上升缺口目标、止损须设在阴线上方——风险与收益几乎打平（报偿比≈1）；几周后的乌云盖顶位置更高，止损（其顶部）与目标（缺口底）距离拉开。
- **结论**: 空头吞噬交易被否决（"形同鸡肋""诱人的陷阱"）；乌云盖顶设定止损/目标后成为"收益不菲的战机"。
- **结果**: 原书定性空头吞噬不应交易、乌云盖顶交易成立；最终盈亏数值未说明（图注显示此后行情一路下跌至 29.5-30.0 美元一带）。

### 示例 2: 60 美元阻挡下一票否决看涨三法
- **类型与来源**: reported_case，上书第七章图 7.28 斯伦贝谢日线
- **问题/输入**: 12 月 29 日收市形成上升三法（还是放宽为 2 根小实体的版本），但恰好位于自 12 月 7 日以来的 60 美元阻挡区域。
- **方法论的使用**: 位置要素不合格——看涨持续形态撞上前期阻挡，一票否决买入；解除条件=收市价站上阻挡。
- **结论/结果**: 等到 1 月 11 日收市于 60 美元阻挡之上，才为继续上行扫清障碍（原书判读如实记录）。

### 示例 3（兼读）: 图 9.1 练兵图
- **类型与来源**: reported_case，上书第九章图 9.1 债券期货日线（38 处编号信号逐点判读）
- 同图示范位置过滤全规则：单根长上影"微不足道"；横向市中的流星轮廓不判流星（先前趋势不匹配）；阻挡窗口之下的刺透形态不能买（其后果然被长黑实体否定）。作者申明判读带主观性："不存在严格、具体的规则，只有一般性的指导要领。"

## A2 — 触发场景 ★

### 用户会在什么情境下需要这张卡？

1. 用户贴出一根/一组 K 线形态并问"能不能按它买/卖"——形态名称已知，缺的是位置过滤与取舍。
2. 用户问"看涨形态出现在均线/前高/套牢区下方，还买吗"——位置与趋势一致性的核对。
3. 上升趋势中出了看跌形态（或反之），用户问"要不要反手/清仓"——方向分派。
4. 用户拿着某个"标准形态"却说不清止损位与目标位在哪——图 4-5 式陷阱的语言信号。
5. 复盘时问"为什么这个形态没灵"——多数答案是位置过滤缺失。

### 语言信号（中英双写）

- "出现了 XX 形态，能买吗 / 该卖吗"（engulfing / hammer / 该不该按形态操作）
- "这个信号准不准、靠不靠谱"（signal reliability, pattern validity）
- "要不要反手 / 要不要清仓"（reversal trade, against the trend）
- "位置对不对 / 是不是高位 / 是不是压力位下"（location, context, support/resistance）

### 与相邻能力卡的区分

- 与 `two-line-reversal` / `star-family` / `umbrella-line-family` 的区别：那些卡判定"形态是否成立、强度如何"；本卡在形态成立**之后**判定"值不值得行动、方向怎么分派"。形态判据不成立时不进入本卡流程。
- 与 `signal-confluence` 的区别：C14 清点**同一价位**的信号群数量并评级区域强度；本卡是单信号的取舍闸门，不数信号群。
- 与 `stop-reward-risk-skill` 的区别：本卡第 4 步只做"是否需要核算"的前置提示；完整止损设定与比值计算由 C20 执行。
- 与 `price-target-retracement-skill` 的区别：本卡不测算目标价；位置四要素只消费既有价位结构。

## E — 执行步骤

**必需输入**: 候选信号（形态名+出现位置描述）+ 当前趋势与价位环境（用户口述或图上转述）。缺先前趋势方向或价位环境时**先询问**，不得静默猜值。
**交付物与完成标准**: 四类动作之一（开新仓候选 / 减仓保护 / 观望 / 放弃）+ 位置评级 + 风险报偿比前置提示。

1. **第 0 步 语义校准**
   - 把"反转形态"重述为"趋势变化"信号：只宣告原趋势终止，之后可能反转/转横/原样继续（汽车刹车灯比喻）；禁用"反转=反向行情"推断。
   - 完成标准：输出中不出现"反转=反向"表述；结论措辞为"趋势变化信号"。

2. **第 1 步 确认先前趋势**
   - 检查形态之前是否存在可被反转的趋势（上升/下降）。
   - 完成标准：写出先前趋势方向及其依据（如"此前 N 根高低点持续抬升"）。
   - **判停**：横盘箱体中部、无趋势可反转 → 直接输出"信号无意义，不动作"并停止该信号的解读。

3. **第 2 步 评估位置四要素**
   - ①趋势方向一致性；②支撑/阻挡环境；③超买/超卖环境；④整数关口与信号群密度（注意：整数关口仅书内单处提及的辅助要素，不作独立卖点）。
   - 位置加持细则：略欠标准的形态（如下影线约 1.8 倍实体的"非标准锤子线"）若落在 50% 回撤位+支撑区，按标准信号同等对待（canonical 判据在 `nonstandard-synthetic-candle`）。
   - 完成标准：四要素逐一给出"合格 / 不合格 / 不适用"。

4. **第 3 步 方向分派**
   - 信号方向与主要趋势一致 → 可开新仓候选；逆向 → 只用于了结/保护（A股落地=卖出既有多头、上调止损；书中期权保护项为美国语境，不迁移）。
   - 强弱倒挂提醒（图 4-5 判例）：重要阻力位的乌云盖顶可以强于普通位置的空头吞噬——形态强度排序让位于位置。
   - 未兑现细则：信号后市场未必立即兑现，可能转为"加强"某支撑区域；未兑现 ≠ 失效。
   - 完成标准：动作方向与主要趋势的关系显式声明。

5. **第 4 步 风险报偿比前置提示 → 交易/放弃**
   - 提示"先算后做"：需要完整核算时转 `stop-reward-risk-skill`（比值合格线书内未给，在该卡自定义声明）。算完不诱人 → 放弃（"拉弓等放弦"）。
   - 完成标准：最终输出为四类动作之一，附位置评级一句话。

## B — 边界 ★

### 不要在以下情况使用此卡
- 形态判据本身不成立（形态学认定错误）——先回对应形态卡重判，本卡不救济判据错误。
- 用户要的是纯行情信息查询（"今天收盘多少"）——不是取舍决策。
- 长阴长阳交错的大幅震荡期——"像 8 级地震"，形态读数半衰期不到一天，正确动作是降频观望，不是逐个过滤信号。

### 书中警告的失败模式
- x02（位置>形态原句出处）：孤立解读形态——"更标准"的空头吞噬反而是"诱人的陷阱"；"形态的位置比形态本身更重要"即出自图 4-5。
- x01（一知半解更危险）：看到形态第一反应是"快下单"而不是"它在哪个位置"；"对蜡烛图的零星认识只会带来危险"。
- x22（压路机比喻）：观点正确但逆势操作照样破产——逆向信号只做保护，不做开新仓依据。
- x06/x18：对非标准形态机械排除同样危险——判据灰色地带须参数化声明，关键位置上欠标准的形态按位置加持处理。
- x24（8 级地震）：震荡期强行交易是"无谓的牺牲"。

### 作者盲点（阶段 0 批判）
- **无统计回测**（G3）：全书为案例+心理逻辑归纳，无命中率/假信号率数据——禁止单形态决策进任何统计承诺。
- **1990s 美国样本**：图例集中在 1990-1994 年美股/美期货，牛市偏差可能抬高信号灵验观感。
- **判据弹性须自测**（G1）："超买超卖"无统一标尺、"整数关口"仅辅助——使用前按标的自测并声明（量化标尺可接 `divergence-index`）。

### A股制度适配注意
- 书中"顺主要趋势开新仓"配套的保护手段含期权项（保护性期权等）——美国市场工具，A股多数标的无对等物，不迁移；A股落地=减仓/清仓+上调止损。
- T+1：逆向信号触发"了结"当日可卖，但据此开新仓次日才能卖——报偿比核算须计入隔夜风险。
- 涨跌停：信号 K 线若为一字板（开=收=高=低），形态内部结构不可读——按数据门（`data-quality-confirmation-gate`）降级处理。
